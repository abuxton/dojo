Map the graph before you inspect it

A schema tells you what a store can represent. It does not require you to view the personal records it contains.

Use a safe traversal

Run the guided sequence. It prints commands only; execute each command deliberately.

cd /Users/abuxton/src/github/dojo
./lessons/apple-intelligence-personal-knowledge-graph/bin/intelligence-platform walk

On this Mac, the schema exposed an entity table with source-fact fields including subject, predicate, and object. It also exposed stable_graph, which adds relationship and confidence fields. Your OS version may differ, so inspect your local schema rather than copying this conclusion.

Abstract before you reveal

These commands return counts and predicate codes, not object values:

./lessons/apple-intelligence-personal-knowledge-graph/bin/intelligence-platform profile entity
./lessons/apple-intelligence-personal-knowledge-graph/bin/intelligence-platform profile stable_graph
./lessons/apple-intelligence-personal-knowledge-graph/bin/intelligence-platform predicate-summary

A high count is not evidence that a specific person, message, or event is stored. It only measures rows or relationship vocabulary in the local database.

Decision point

Only write a direct query when you can state its minimum columns, filter, and limit. Keep its output local. See the reference for the sequence, then ask your teacher before moving from aggregates to records.
